# 아이디어 작업실 — 학생용 React 데모

실제 Spring Boot API를 직접 클릭해 보는 별도 React/Vite 프로젝트다. 기존 학생 프론트 코드를 대체하지 않는다.

## 실행

백엔드를 프로젝트 루트의 `scripts/start-local.ps1`로 먼저 실행한다. 그 다음 별도 창에서:

```powershell
cd demo-web
npm ci
npm run dev
```

[http://127.0.0.1:5173/](http://127.0.0.1:5173/)에서 회원가입·로그인 후 사용한다. 루트의 `scripts/start-demo.ps1`도 같은 개발 서버를 시작한다. 계정을 자동 생성하거나 인증을 우회하지 않는다.

기본 백엔드는 `http://127.0.0.1:8080`이며 `/app/`, `/common/`, `/s/` 요청만 프록시한다. 다른 로컬 서버는 `DEMO_API_TARGET` 환경변수로 지정한다. 브라우저 Origin은 백엔드 `CORS_ORIGINS`에 명시해야 한다. `/s/`의 끝 슬래시를 빼면 `/src`까지 프록시되므로 유지한다.

## 테스트와 빌드

```powershell
npm test
npm run test:watch
npm run build
npm run preview
```

`npm run build`는 React 테스트가 모두 성공해야 배포 파일을 만든다. 루트의 `scripts/build.ps1` 또는 Gradle `build`에도 이 작업이 연결되어 있다. 결과는 `test-results/junit.xml`, 배포 파일은 `dist/`다. `preview`도 5173 포트를 사용하므로 개발 서버와 동시에 켜지 않는다.

## 시연 흐름

1. 회원가입하고 로그인한다.
2. 카테고리를 선택하거나 나만의 카테고리를 미리 보고 추가한다.
3. 세 단어를 뽑고 최대 2개 고정·다시 뽑기를 확인한다.
4. 생성 결과를 보고 같은 단어로 다시 조합하거나 확정한다.
5. 음식은 만드는 법, 프로그램은 구현 가이드, 공모전은 기획안을 확인한다. 직접 만든 카테고리는 생성할 때 고른 유형의 가이드 또는 기본 실행 계획을 확인한다. 결과 전체를 내 기록에 저장한다.
6. 링크를 복사하거나 피드에 게시한다.
7. 로그아웃한 뒤 다른 계정을 만들어 첫 계정의 피드 글에 반응·변경·취소한다.

오른쪽 LIVE LAB에서 요청·응답·소요 시간을 설명할 수 있다. 인증 정보는 출력하지 않는다. 서버가 mock이면 화면도 ‘시연 예시’로 표시하고, Gemini 설정이면 실제 생성 결과를 보여 준다.

## 수정할 곳

- `src/App.jsx`: 공통 상태, 요청 처리, 화면 전환.
- `src/components`: 로그인, 생성 흐름, 만드는 법, 피드, 내 기록.
- `src/api.js`: API 요청·오류·한 번의 토큰 갱신·세션.
- `src/storage.js`: 브라우저 내 기록의 전체 스냅샷.
- `src/styles.css`: 반응형 화면.
- `src/*.test.*`: API 클라이언트·사용자 클릭·저장·프록시 회귀 테스트.

전체 범위·실패/성공 기록·MySQL 분리 원칙은 [테스트와 시연 안내](../docs/TESTING_AND_DEMO.md)를 참고한다.
